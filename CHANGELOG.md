# Журнал изменений (Changelog)

Все заметные изменения в этом проекте будут задокументированы в этом файле.

Формат основан на [Keep a Changelog](https://keepachangelog.com/en/1.0.0/), и проект придерживается [Семантического Версионирования](https://semver.org/spec/v2.0.0.html).

---

## [0.6.0] - 2026-10-31

### Added (Добавлено)
- **Подкоманды Google Drive в CLI (`utils/cli_v3.py`):**
  - `fetch-drive`: поиск и скачивание чатов из папки "Google AI Studio" по имени или подстроке, с поддержкой сквозного пайплайна (`--parse`, `--distill`, `--log_to_memory`).
  - `auth-drive`: интерактивная авторизация OAuth2 consent flow для генерации локального токена.
- **Модуль аутентификации Google Drive (`utils/drive/auth.py`):** Загрузка OAuth2-кредов из переменных окружения (`GDRIVE_CLIENT_ID`, `GDRIVE_CLIENT_SECRET`, `GDRIVE_REFRESH_TOKEN`) или локального файла `.gdrive_token.json`, автоматический refresh.
- **Клиент Google Drive (`utils/drive/client.py`):** Класс `GoogleDriveChatFetcher` для поиска папки, скачивания raw JSON и защиты от неоднозначных совпадений.
- **Тесты трансформации схем (`tests/test_transformation.py`):** Полное покрытие тестами `SchemaTransformer` (OpenAI ↔ Gemini SchemaData ↔ Python Schema).
- **CI/CD Workflow (`.github/workflows/ci.yml`):** Автоматический запуск тестов pytest и линтера ruff для Python 3.10, 3.11, 3.12 при push и PR в ветки `main` и `dev`.

### Changed (Изменено)
- **Legacy-тесты актуализированы:** Восстановлены и адаптированы `tests/test_parsing.py`, `tests/test_reconstruction.py`, `tests/test_studio_json_reconstruction.py` под актуальные тестовые фикстуры `data/Example`.
- **Конфигурация pytest:** Добавлена опция `pythonpath = ["."]` в `pyproject.toml`, устраняющая необходимость вручную настраивать `PYTHONPATH`.
- **Исправление синтаксиса:** Устранена несовместимость escape-последовательностей внутри f-строк в `google_studio_parser.py` для поддержки Python < 3.12.

## [0.5.0] - 2026-09-30

### Added (Добавлено)
- **Подпапки вывода для `parse`:** Каждый входной файл получает отдельную подпапку `<output_prefix>/<safe_stem>/` с тремя артефактами (`_intermediate.json`, `_raw_rag.md`, `_human.md`). Имя папки идемпотентно (повторный запуск перезаписывает, не плодит `-2`, `-3`).
- **Новая команда `distill`:** Дистилляция уже готовых `_human.md` файлов через LLM без повторного парсинга. Поддерживает `--input_file` и `--input_dir`.
- **Опция `--distill` для `parse`:** После парсинга автоматически запускает дистилляцию сгенерированных `_human.md`.
- **Пакет `utils/distillation/`:** Модули `safe_stem`, `chunker`, `redactor`, `llm_client`, `verifier`, `pipeline` — полный конвейер дистилляции.
- **Редакция секретов:** Детерминированный regex-фильтр (11 паттернов: sk-ключи, JWT, Bearer, Linear, GitHub, Google, AWS, Slack, PEM, URL-параметры, key-value) перед отправкой в LLM.
- **Детерминированный верификатор:** Проверка покрытия ходов, дословности код-блоков, отсутствия секретов в результате, валидности frontmatter.
- **Кэш вызовов LLM:** `.distill_cache/` рядом с выходом; ключ включает текст чанка, промпт, модель и `base_url`. Повторный запуск переиспользует результаты.
- **`httpx` добавлен в `requirements.txt`** (транспорт для OpenAI-совместимого API).

### Changed (Изменено)
- `--output_prefix` для `parse` теперь трактуется как **базовая папка**, а не префикс имени файла.
- `safe_stem` заменяет `#`, `%`, `&` и другие URL/FS-небезопасные символы на `_` (решение для совместимости с Obsidian/OmniWiki ссылками).

### Безопасность
- Редакция секретов запускается всегда перед отправкой текста в LLM.
- Существующие `_distilled.md` не перезаписываются (флага `--force` нет; пересчёт = ручное удаление).

## [0.4.0] - 2026-05-04

### Added (Добавлено)
- **Интеграция с Memory Compiler:** Добавлен флаг `--log_to_memory` (или `-l`) в команду `parse`. При его использовании содержимое сгенерированного `human.md` файла автоматически отправляется в дневной лог проекта в Memory Compiler.
- **Новая команда `log`:** Добавлена новая подкоманда `log` в `cli_v3.py`. Она позволяет вручную отправлять содержимое любого текстового файла (.md, .txt) в Memory Compiler.
  - **Использование:** `python utils/cli_v3.py log -i <путь_к_файлу> -s <название_секции>`

### Changed (Изменено)
- **Управление ветками:** Основная ветка разработки переименована с `master` на `main` для соответствия современным стандартам. Создана ветка `dev`.

## [3.0.0] - (Предыдущая мажорная веха)

### Added (Добавлено)
- **Полноценная объектно-ориентированная архитектура:** Проект реструктурирован в Python-библиотеку с классами (`GoogleAIStudioJSONParser`, `GeminiAPICodeReconstructor`, `SchemaTransformer`).
- **Пакет `core` с моделями данных:** Введены строго типизированные классы для всех элементов чата, что повышает надежность.
- **CLI с подкомандами:** Реализован единый интерфейс командной строки `utils/cli_v3.py` с подкомандами (`parse`, `reconstruct`, `apply_overrides_to_studio_json`).
- **Поддержка файлов-оверрайдов:** Добавлена возможность динамически изменять системную инструкцию (`.si`), первое (`.fi`) и последнее (`.li`) сообщения при реконструкции и патчинге Studio JSON (`apply_overrides_to_studio_json`).
- **Утилита для объединения Markdown:** Добавлен отдельный инструмент `tools/markdown_merger.py`.

### Changed (Изменено)
- **Логика парсинга и реконструкции** инкапсулирована в соответствующие классы, а не находится в отдельных скриптах.

## [2.0.0]

### Added (Добавлено)
- **Поддержка парсинга сырых JSON-экспортов** из Google AI Studio.
- **Концепция "стандартизированного промежуточного JSON"** как единого формата данных после парсинга.
- **Несколько шаблонов для реконструкции** (`vanilla`, `dynamic_si`, `google_vanilla`) для большей гибкости.
- **Инструмент `schema_transformer.py`** для конвертации JSON Schema между форматами OpenAI и Gemini.
- **Информативный вывод в CLI** с пошаговым отчетом о выполнении.

### Changed (Изменено)
- **Ключевое изменение: Отказ от парсинга `.py` файлов.** Проект перешел на работу с более надежным и чистым форматом JSON-экспорта, что значительно повысило стабильность.

---

## [1.0.0] - (Начальная версия)

### Added (Добавлено)
- **Базовый парсер (`parser.py`)** для извлечения данных из `.py` файлов, экспортированных из Google AI Studio.
