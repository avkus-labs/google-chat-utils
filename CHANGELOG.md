## [0.7.5] - 2026-11-01

### Added (Добавлено)
- **Поддержка чатов «только System Instruction» (режим документа, задача 007):**
  - **Детектор `is_si_only(text)`:** определяет файлы, содержащие `### System Instruction` и не имеющие ни одного хода `### **User**` или `### **Model**` (после удаления мыслей).
  - **Флаг `--distill_si_only {document,skip}`:** задаёт стратегию обработки таких файлов во всех командах (`parse`, `distill`, `fetch-drive` и интерактивном меню). По умолчанию — `document`.
  - **Режим `document`:**
    - Текст секции System Instruction берётся целиком (blockquote сохраняется) и проходит очистку секретов (`redact_secrets`).
    - Оценка объёма в токенах (`chars / 2.0`): если превышает `chunk_tokens`, дистиллятор завершается с ошибкой `DistillError` с указанием необходимости ручной обработки.
    - Выполняется ровно один вызов LLM на synthesis-модели (`prompts/distiller_synthesis_prompt.md` с обёрткой `<distilled_text kind="document">`) для генерации метаданных (title, summary, keywords, tags, decisions, lessons). Поля `resolution`, `failed_approaches`, `error_signatures` для документов не используются.
    - Записывается файл `<stem>_distilled.md` (атомарно): frontmatter содержит `chunks: 0`, `source_kind: system_instruction`, `trust_tier: ai-generated`, блок `verification:` без проверки покрытия ходов (`turn_coverage`); тело содержит заголовок `# <title>`, аннотацию, секцию `## System Instruction` с дословным текстом инструкции и раздел `## Ключевая информация`.
  - **Режим `skip`:** прежнее поведение с отказом и сообщением об отсутствии заголовков ходов (`exit_code=2`).
  - **Верификатор:** для файлов с `source_kind == "system_instruction"` проверка покрытия ходов пропускается (не является предупреждением), валидация секретов остаётся в силе.
  - **План дистилляции:** для SI-only файлов в выводе плана отображается `режим=SI-документ, ~вход=<N> ток.`.

## [0.7.4] - 2026-11-01

### Added (Добавлено)
- **Целостность дистилляции и честная верификация (задача 006):**
  - **Защита от пустых ответов LLM (006.A):** пустой ответ в `chat_completion` (как при стриминге, так и в обычном режиме) теперь считается ошибкой модели (`ChunkFailedError("empty response")`) с ретраями; пустые строки и пробелы никогда не записываются в кэш (`DistillCache.put`), а ранее попавшие в кэш пустые значения трактуются как промах (`cache.get(...) is None`). Пустой ответ synthesis вызывает `DistillError`.
  - **Честные статусы верификации (006.B):** статусы `ok` | `warning` | `error`. Статус становится `warning`, если обнаружены непокрытые ходы, якоря-заглушки (`(ходы N–N)`, `(ходы [не указаны])`, `[не указан]`), якоря вне диапазона ходов или подозрительные блоки кода (>30% отсутствующих строк). Статус `error` зарезервирован для найденных секретов.
  - **Компактный блок `verification:` во frontmatter (006.B):** записываются статус, число и сжатые диапазоны пропущенных ходов (например, `пропущено 72, диапазоны: 1-9, 43-54, 80-126`), число ошибок якорей `anchor_issues`, число подозрительных блоков кода и `length_ratio`.
  - **Строгий режим (`--distill_strict`, 006.B):** новый флаг командной строки для `parse`, `distill`, `fetch-drive` и интерактивного меню. При неполном покрытии ходов (< 100%) или любых ошибках якорей прерывает процесс с кодом ошибки `exit=2`, не записывая файл (кэш успешных чанков сохраняется).
  - **Построчная проверка кода без ложных срабатываний (006.C):** нормализация текста (CRLF→LF, серии пробелов/табов, многоточия `…`→`...`, типографские кавычки и тире → ASCII). Блок считается подозрительным только если в источнике не найдено более 30% его непустых строк (порог от 2 строк).
  - **Обработка чатов без реплик пользователя (006.D):** если после очистки мыслей и System Instruction в диалоге нет заголовков `### **User**` (реплики удалены вручную), в начало подготовленного текста добавляется служебная пометка `[примечание пайплайна: ...]`; в `plan_line` выводится `⚠ нет реплик пользователя`; в промпты добавлено правило, запрещающее метку `[подтверждено]` для таких чатов. Если суммарный текст ходов короче 200 символов, файл пропускается с явным сообщением.
  - **Контрольная сумма источника:** задокументировано, что `source_sha256` вычисляется по тексту после нормализации переводов строк (universal newlines, CRLF → LF).

## [0.7.3] - 2026-10-31

### Added (Добавлено)
- **Стриминг в клиенте дистилляции (`chat_completion`, задача 005):**
  - **SSE-стриминг по умолчанию (`stream=True`):** запросы к LLM теперь по умолчанию отправляются со `stream: true` через `httpx.stream`. Первые байты приходят сразу, что устраняет зависимость от таймаутов ожидания шлюза (OmniRoute).
  - **Флаг `--llm_no_stream`:** отключает стриминг и возвращает стандартный блокирующий `httpx.post`. Доступен в командах `parse`, `distill` и `fetch-drive`.
  - **Построчный разбор SSE:** поддерживаются строки `data: <json>` и терминатор `data: [DONE]`; комментарии keep-alive (`: ...`), пустые строки, события без `choices` (например, статистика usage) и невалидный JSON в keep-alive безопасно игнорируются; поля рассуждений (`reasoning_content`, `reasoning`, `thinking`) в контент не включаются.
  - **Обработка ошибок и ретраи:** статус ответа проверяется до вычитывания тела (`RETRYABLE_STATUS` 429/5xx ретраятся с экспоненциальным backoff, 4xx фатальны с чтением первых 200 байт); обрыв соединения до `finish_reason` или событие `error` в потоке считаются сетевой ошибкой и перезапускают запрос с очисткой частично собранного текста.
  - **Проверка завершения:** `finish_reason` извлекается из последнего непустого события (`finish_reason != "stop"` вызывает `ChunkFailedError`).
  - **Семантика таймаута:** таймаут `timeout=600.0` конфигурируется как `httpx.Timeout(timeout, connect=30.0)` и задаёт паузу между байтами/чанками (read timeout), а не общее время ответа.
  - **Раздел «Почему стрим»:** задокументированы причины перехода на SSE (таймауты OmniRoute `requestQueue.maxWaitMs=15000ms`, `Direct response did not start within 30000ms`, `409 duplicate request` при повторе на другом аккаунте).
- **Рекурсивный поиск файлов в `distill --input_dir`:**
  - Поиск файлов `*_human.md` в команде `distill` теперь выполняется рекурсивно по всем вложенным директориям с автоматическим игнорированием скрытых каталогов и кэша (`.distill_cache`). Это позволяет передавать общую директорию `output_data` как через CLI, так и в интерактивном меню по умолчанию.
- **Исправление работы интерактивного режима дистилляции (`interactive`):**
  - Функция `build_distill_config` переведена на безопасное извлечение атрибутов через `getattr` со значениями по умолчанию из `DistillConfig`, предотвращая ошибку отсутствия атрибута `llm_api_key_env`.
  - В интерактивном режиме дистилляции обеспечена корректная передача параметров по умолчанию и флага `dry_run` (`distill_dry_run`).

## [0.7.2] - 2026-10-31

### Added (Добавлено)
- **Отдельная модель для synthesis (`--llm_synthesis_model`, задача 004):**
  - **Флаг `--llm_synthesis_model`:** позволяет использовать более сильную модель на шаге synthesis (структурирование метаданных и JSON) и более дешёвую/быструю `--llm_model` для обработки чанков диалога. Доступен в командах `parse`, `distill` и `fetch-drive`.
  - **Поведение по умолчанию:** если `--llm_synthesis_model` не задан (пустая строка), для synthesis используется `--llm_model` (полная обратная совместимость).
  - **Кэширование:** смена synthesis-модели не инвалидирует кэш чанков; повторный прогон берет обработанные чанки из кэша и вызывает LLM только для synthesis.
  - **Frontmatter `_distilled.md`:** `generated.by` всегда содержит модель чанков; если synthesis-модель отличается, в frontmatter добавляется верхнеуровневый ключ `synthesis_model: "<имя>"`.
  - **План дистилляции:** вывод плана дистилляции и dry-run теперь явно указывает используемые модели: `модели: чанки=<A>, synthesis=<B>`.
  - **Интерактивный режим (`interactive`):**
    - Добавлен запрос «Модель для synthesis (Enter = та же):».
    - Убран неявный дефолт `"qwen2.5:14b"`: при отсутствии переменной окружения `DISTILLER_MODEL` и пустом ответе выводится понятное сообщение об ошибке с отказом без дефолта.
  - **Тесты:** добавлен тестовый набор `tests/test_synthesis_model.py` (10 тестов: вызовы чанков и synthesis на разных моделях, retry невалидного JSON на synthesis-модели, сохранность кэша чанков при смене synthesis, frontmatter, парсинг CLI и интерактивный режим).

## [0.5.0] - 2026-09-30

### Added (Добавлено)
- **Подпапки вывода для `parse`:** Каждый входной файл получает отдельную подпапку `<output_prefix>/<safe_stem>/` с тремя артефактами (`_intermediate.json`, `_raw_rag.md`, `_human.md`). Имя папки идемпотентно (повторный запуск перезаписывает, не плодит `-2`, `-3`).
- **Новая команда `distill`:** Дистилляция уже готовых `_human.md` файлов через LLM без повторного парсинга. Поддерживает `--input_file` и `--input_dir`.
- **Опция `--distill` для `parse`:** После парсинга автоматически запускает дистилляцию сгенерированных `_human.md`.
- **Пакет `utils/distillation/`:** Модули `safe_stem`, `chunker`, `redactor`, `llm_client`, `verifier`, `pipeline` — полный конвейер дистилляции.
- **Редакция секретов:** Детерминированный regex-фильтр (11 паттернов: sk-ключи, JWT, Bearer, Linear, GitHub, Google, AWS, Slack, PEM, URL-параметры, key-value) перед отправкой в LLM.
- **Детерминированный верификатор:** Проверка покрытия ходов, дословности код-блоков, отсутствия секретов в результате, валидности frontmatter.
- **Кэш вызовов LLM:** `.distill_cache/` рядом с выходом; ключ включает текст чанка, промпт, модель и `base_url`. Повторный запуск переиспользует результаты.
- **`httpx` добавлен в `requirements.txt`** (транспорт для OpenAI-совместимого API).

### Changed (Изменено)
- `--output_prefix` для `parse` теперь трактуется как **базовая папка**, а не префикс имени файла.
- `safe_stem` заменяет `#`, `%`, `&` и другие URL/FS-небезопасные символы на `_` (решение для совместимости с Obsidian/OmniWiki ссылками).

### Безопасность
- Редакция секретов запускается всегда перед отправкой текста в LLM.
- Существующие `_distilled.md` не перезаписываются (флага `--force` нет; пересчёт = ручное удаление).
